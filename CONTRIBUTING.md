# Contributing to Teep

Thanks for your interest. Teep is a one-person project and I'd like to keep the contribution model honest about that.

## What's welcome

- **Bug reports** — open an issue with a minimal repro, your terminal + OS, and what you expected vs. what happened.
- **Feature requests** — also as issues. Happy to hear what would make Teep better, even if I can't commit to shipping it.
- **Security reports** — please email **teep@teep.app** directly rather than filing a public issue.

## What's not currently accepted

- **Pull requests.** I'm not reviewing drive-by code contributions right now. The codebase is small and I'd like to keep it coherent while the shape is still settling. If that changes, this file will change.

Please don't take "no PRs" personally — it's a bandwidth and direction decision, not a judgment of your code.

## If you really want to contribute code

Fork it. That's what OSS licenses are for. If your fork does something I want to land upstream, get in touch at **teep@teep.app** and we can talk about it.
